## Concrete gaps to resolve or explicitly account for

1. **Package/network authorization bypass and swapped arguments (W3.18/W3.19; original P0 #13/#14/#16 policy).** `B/CommandRegistry.cs:451-457` reads `includeIndirect`/`includeOffline` and passes them as `Client.List(includeIndirect, includeOffline)`. Unity 2022.3 declares `Client.List(bool offlineMode, bool includeIndirectDependencies)`: false offlineMode requests current registry information. Therefore a normal authenticated `package_list` with `includeIndirect:false` bypasses the default-denied package/network class (`B/BridgeSecurity.cs/RequiresPackageCapability` covers search/add/remove only), and TS reports read/closed-world metadata. The parameter order and network effect were confirmed against the [official Unity 2022.3 Client.List documentation](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/PackageManager.Client.List.html). No live network call was made by this trace.
2. **Maximum nested risk drift (W3.20/W7.2/W7.11; original P0 #14).** `B/CommandRegistry.Batch.cs/ResolveBatchPolicy` gives screenshot baseline cleanup asset-write, whereas the public operation and destructive gate identify deletion. Existing batch tests cover a destructive GameObject path, not this policy row. Scope is a finite risk parity correction and its regression, not a whole-domain rewrite.

They do not compare request/response schemas, risk, Undo, dry-run, or permission policies against C#. The required comprehensive parity has not been implemented. 5. **Version/capability handshake (W3.14).** Versions and capabilities are written to disk, but no client handshake validation/negotiation consumes them before requests. The health response does not include enabled capabilities and isConnected accepts any successful decoded health reply.
